# CS180 Project 4A: Image Warping and Mosaicing

Shoot photos, recover homographies, warp images (nearest neighbor and bilinear, inverse warping),
rectify flat rectangles, and blend photos into mosaics. The homography and warping code is my own
(no `cv2.findHomography`, `cv2.warpPerspective`, `skimage.transform.warp`, etc.).

Spec: https://cal-cs180.github.io/fa26/hw/proj3/partA.html
Webpage: https://yponvon.github.io/4/

## Folders

```
4/
├── code/                   all my code (run from this folder)
│   ├── paths.py            where every script reads/writes images
│   ├── warp.py             the algorithms: computeH, nearest/bilinear inverse warping, mosaic blending
│   ├── pick_points.py      click correspondences / rectangle corners, saved to points/
│   ├── part2_homography.py A.2 (correspondences, system of equations, H)
│   ├── part3_rectify.py    A.3 (rectification, nearest vs bilinear)
│   ├── part4_mosaic.py     A.4 (mosaics: overwrite vs weighted average vs 2-band blend)
│   └── main.py             runs part2 – part4 in order
├── points/                 clicked points, one json per pair or rectangle
└── images/
    ├── mine/               my photos
    ├── unused/             photos I took but didn't use (not committed)
    └── results/            every figure the webpage shows (generated by the scripts)
```

How the points were made: the two `anthro_*` pairs were clicked by hand with `pick_points.py`. For the other
pairs, rough matches were placed on clear features and each point was snapped to the exact matching pixel with
normalized cross-correlation on small patches. The rectangle corners were placed by hand on zoomed crops.

Result filenames start with the part they belong to: `a2_`, `a3_`, `a4_`.

## Running

```
pip install numpy opencv-python matplotlib
cd code
# 1. click points (left click adds, right click removes, close the window to save)
#    mosaics: each photo -> its neighbour one step closer to the reference photo
#    (all the point files are already in points/, running a command again lets you edit them)
python pick_points.py anthro_left.jpg anthro_mid.jpg anthro_left_mid
python pick_points.py anthro_right.jpg anthro_mid.jpg anthro_right_mid
python pick_points.py sunshade_left.jpg sunshade_right.jpg sunshade_left_right
python pick_points.py terrace_1.jpg terrace_2.jpg terrace_1_2
python pick_points.py terrace_2.jpg terrace_3.jpg terrace_2_3
python pick_points.py terrace_4.jpg terrace_3.jpg terrace_4_3
python pick_points.py terrace_5.jpg terrace_4.jpg terrace_5_4
#    rectification: 4 corners, clockwise from top-left
python pick_points.py rect_map.jpg rect_map
python pick_points.py rect_box.jpg rect_box
# 2. run everything
python main.py
```

Which photos make up each mosaic is set in `MOSAICS` at the top of `part4_mosaic.py`, and the rectangles
(with their width/height) in `RECTIFY` at the top of `part3_rectify.py`. The terrace has 5 photos, so the
outer ones are chained through their neighbours to the middle photo instead of matched to it directly.

Photos: `anthro_*` Anthropology & Art Practice building, `sunshade_*` the concrete building with sunshades,
`terrace_1` … `terrace_5` Chuk Wong Terrace (left to right), `rect_map` campus map sign, `rect_box` a
hand cream box on my shelf.

numpy 2.0 on Mac prints harmless "divide by zero encountered in matmul" warnings, the results are fine.
